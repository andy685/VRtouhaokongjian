# VR头号空间 — 非加盟模式营销方案 v1.0

> 编写日期：2026-09-03
> 状态：方案探讨

---

## 一、业务背景

### 1.1 原模式（加盟制）

- 商家加盟平台，使用平台全套系统（收银、会员、分账）
- 用户充值走平台收银台，资金过平台再分账给商家
- 平台通过拉卡拉自动分账或人工打款完成结算
- 平台掌控全链路：获客 → 支付 → 分账 → 会员

### 1.2 变更原因

- 加盟业务受限，资金池风险
- 商家希望自主经营，使用自己的收银系统和会员系统

### 1.3 新模式（非加盟制）

- 平台只卖机器和游戏豆给商家（B2B 供应商）
- 商家自主定价、自主收银、自主管理会员
- 平台与商家之间仅剩游戏豆采购关系
- 平台收入来源：游戏豆批发差价 + 机器销售

---

## 二、平台与商家的关系边界

| 维度 | 平台负责 | 商家负责 |
|---|---|---|
| 机器 | 提供、维护 | 日常运营 |
| 游戏豆 | 批发销售 | 采购、消耗 |
| 收银 | 不参与 | 自有收银系统 |
| 会员 | 不参与 | 自有会员系统 |
| 定价 | 不参与 | 自主定价 |
| 营销 | 小程序获客、体验券发放 | 核销体验券、到店转化 |
| 数据 | 小程序用户数据、豆账户 | 自有经营数据 |

**核心原则：平台不碰商家的收银和会员，商家不碰平台的用户和豆账户。**

---

## 三、营销方案概述

### 3.1 目标

平台通过小程序获客，用体验券驱动玩家到店，帮商家引流，间接拉动游戏豆消耗。

### 3.2 核心闭环

```
平台投放广告 → 玩家进入小程序注册
    → 做任务攒积分 → 兑换体验券
    → 带券到店 → 商家微信扫码核销
    → 玩家免费玩一局 → 平台补偿商家游戏豆
    → 玩家体验好 → 下次自费来 → 商家获得回头客
    → 玩家分享/邀请 → 拉新 → 循环
```

### 3.3 关键特征

- 不需要在店里放任何码
- 不需要机器配合
- 不需要对接商家系统
- 商家只需微信扫一扫
- 全部验证在线上完成
- 全部正向激励，没有评价、打分、差评

---

## 四、小程序功能设计

### 4.1 首页 — 任务墙

玩家进入小程序看到任务列表，每个任务标注积分奖励，引导玩家完成任务攒积分。

**设计原则：**
- 所有任务平台自己能验证，不依赖线下
- 全部正向激励，没有评价、打分、差评
- 任务简单，门槛低，新用户快速拿到第一张体验券

### 4.2 积分钱包

- 当前积分余额
- 积分获取记录（时间、任务、积分）
- 积分消耗记录（时间、兑换内容）
- 积分规则说明

### 4.3 体验券

- 当前可用体验券数量
- 体验券二维码（点击"使用"生成一次性码）
- 可用店铺列表（文字+地址，非地图）
- 使用记录（何时在哪家店核销）
- 体验券规则说明（有效期、适用店铺、使用时段限制）

### 4.4 邀请有礼

- 生成专属邀请海报/链接（带小程序码）
- 已邀请人数、已注册人数
- 邀请奖励记录

### 4.5 个人中心

- 昵称、头像、城市
- 积分余额
- 体验券数量
- 邀请人数
- 注册时间、签到天数

### 4.6 可用店铺列表

- 展示参与体验券活动的店铺
- 每家店：店名、地址、营业时间、游戏列表（选填）、店铺图片（选填）
- 玩家通过列表了解去哪家店，不需要地图
- 后期参与商家多了（单城市 20 家以上）再考虑做 LBS 地图

## 五、积分体系

### 5.1 获取规则

| 行为 | 积分 | 说明 |
|---|---|---|
| 注册 | 赠 1 张体验券 | 不发积分，直接发券，降低新用户门槛 |
| 每日签到 | +5 | 连续签到 7 天额外 +20 |
| 分享店铺 | +20 | 每日限 1 次 |
| 邀请好友注册 | +50 | 好友注册成功后到账 |
| 看游戏介绍 | +10 | 每款游戏限 1 次 |
| 完善资料 | +10 | 一次性 |

### 5.2 消耗规则

| 兑换项 | 积分 | 说明 |
|---|---|---|
| 体验券（通用） | 200 积分 | 免费玩一局，到店核销 |
| 体验券（工作日） | 120 积分 | 限工作日使用，帮商家填闲时 |

### 5.3 积分有效期

- 积分自然年内有效，年底清零
- 体验券领取后 30 天有效
- 促使玩家及时使用，不囤积

---

## 六、体验券体系

### 6.1 发放渠道

| 渠道 | 数量 | 目的 |
|---|---|---|
| 新用户注册 | 1 张 | 降低首次体验门槛 |
| 积分兑换 | 按积分 | 留存核心手段 |
| 平台活动 | 不定 | 节假日、新店开业、新游戏上线时额外发放 |

### 6.2 体验券规则

- 每张体验券限指定店铺使用（或通用，由平台配置）
- 每张体验券限核销 1 次
- 有效期 30 天
- 可设置使用时段限制（如仅工作日、仅闲时）
- 核销后不可退回

### 6.3 核销流程

```
1. 玩家在小程序点"使用体验券"
2. 选择到店店铺（或通用券无需选）
3. 生成一次性二维码（有效期 10 分钟）
4. 到店出示二维码给商家
5. 商家打开微信扫一扫，扫描二维码
6. 跳转平台核销网页
7. 网页显示：券类型、适用店铺、有效期、补偿豆数量
8. 商家点"确认核销"
9. 券作废，平台自动给商家豆账户补发游戏豆
10. 玩家免费玩一局
```

**商家端要求：**
- 只需要微信，不需要装 App
- 不需要注册平台账号
- 扫码后打开的是平台网页，点一个按钮即可
- 核销记录可在平台商家后台查看

### 6.4 防刷机制

- 每个用户同时只能有 1 张未使用的体验券
- 体验券二维码 10 分钟过期，过期需重新生成
- 同一用户同一店铺 7 天内最多核销 1 张
- 邀请奖励在好友注册后才发放，防止虚假邀请
- 积分异常增长触发风控审核

---

## 七、商家参与机制

### 7.1 参与方式

- 商家自愿参与体验券活动
- 参与的店铺出现在小程序可用店铺列表中
- 不参与的店铺不展示，不获得平台流量

### 7.2 商家收益

| 收益 | 说明 |
|---|---|
| 免费客流 | 平台投放广告带来的新玩家 |
| 豆补偿 | 每核销 1 张体验券，平台补偿对应游戏豆 |
| 闲时填充 | 工作日体验券帮商家提升闲时利用率 |
| 零成本 | 不需要装系统、不需要放码、不需要对接 |

### 7.3 商家准入条件

- 已采购平台机器
- 游戏豆账户余额充足
- 填写店铺信息（店名、地址、营业时间、游戏列表、店铺图片）
- 同意体验券核销规则

### 7.4 商家后台（平台提供）

平台给商家开一个简单 Web 后台（手机号登录）：

- 店铺信息管理（编辑店名、地址、营业时间、游戏列表、店铺图片）
- 体验券核销记录（时间、券号、补偿豆数）
- 游戏豆余额和消耗记录
- 可设置：是否参与体验券活动、体验券使用时段限制

## 八、平台获客策略

由于店里没有任何平台触点，平台必须主动往外获客。

### 8.1 广告投放

| 渠道 | 内容 | 目标人群 |
|---|---|---|
| 抖音 | "免费体验 VR 游戏"短视频 + 信息流广告 | 泛娱乐用户 |
| 小红书 | "周末去哪玩 VR"种草笔记 | 年轻女性、情侣 |
| 微信朋友圈广告 | LBS 定向，附近 5km | 本地用户 |
| 美团/大众点评 | 店铺入驻或合作 | 搜索意图用户 |

### 8.2 内容运营

- 小程序内做"VR 游戏库"：每款游戏介绍、适合人群、时长、难度
- 运营公众号/视频号：VR 游戏评测、新游戏上线、店铺探店
- 让小程序本身有内容价值，玩家主动来用

### 8.3 裂变获客

- 邀请有礼：邀请好友注册，双方各得 50 积分
- 分享店铺：分享到朋友圈得 20 积分
- 体验券自带裂变：玩家到店体验后，商家引导"扫码领你的体验券"（可选，商家自愿）

### 8.4 合作获客

- 和本地生活号合作推广
- 和学校社团、企业团建渠道合作
- 新店开业时平台集中投放该区域广告

## 九、系统架构

### 9.1 需要新建的系统

| 系统 | 说明 | 技术建议 |
|---|---|---|
| 玩家小程序 | 任务墙、积分钱包、体验券、可用店铺列表、邀请 | 微信小程序 + 云开发或后端 API |
| 核销网页 | 商家扫码打开，确认核销 | H5 页面，无需登录，扫码即用 |
| 商家后台 | 店铺信息管理、核销记录、豆账户 | Web 后台（可复用现有 admin-dashboard） |
| 平台后台 | 任务管理、体验券发放、广告投放管理、数据看板 | Web 后台（复用现有 admin-dashboard） |
| 后端 API | 用户、积分、体验券、店铺、豆账户、核销 | 云函数或独立后端服务 |

### 9.2 复用现有系统

| 现有系统 | 复用方式 |
|---|---|
| admin-dashboard | 新增"营销管理"模块（任务配置、体验券管理、数据看板）+ "商家管理"模块（店铺信息、豆账户） |
| 游戏豆账户体系 | 已有，商家采购豆的流程不变，新增"体验券核销补偿豆"的自动入账 |
| 机器管理 | 不变，机器销售流程保留 |

### 9.3 逐步废弃的系统

| 系统 | 处理 |
|---|---|
| cashier-ui（收银台） | 商家不再使用，可保留给直营店或下线 |
| 分账管理（SettlementManage） | 简化为游戏豆采购记录 |
| 结算配置（SettlementConfig） | 简化为游戏豆批发价/折扣配置 |
| 拉卡拉分账对接 | 不再需要 |

## 十、成本分析

### 10.1 平台成本

| 项目 | 成本类型 | 说明 |
|---|---|---|
| 体验券豆补偿 | 虚拟成本 | 游戏豆是虚拟货币，边际成本接近零 |
| 广告投放 | 真金白银 | 抖音/小红书/微信广告费，主要支出 |
| 小程序开发 | 一次性 | 开发成本 |
| 后端服务 | 持续 | 服务器、云函数费用 |
| 运营人力 | 持续 | 内容运营、广告优化、商家沟通 |

### 10.2 收入来源

| 项目 | 说明 |
|---|---|
| 游戏豆批发 | 商家采购游戏豆，核心收入 |
| 机器销售 | 一次性收入 |
| 广告位 | 小程序可用店铺列表可做付费排名（后期） |

### 10.3 ROI 逻辑

```
平台投放广告 → 获客成本 X 元/人
    → 玩家到店核销体验券 → 平台补偿豆（虚拟成本 ≈ 0）
    → 玩家体验后自费再来 → 商家消耗更多豆 → 商家采购更多豆
    → 平台收入 = 豆批发利润
    → 当 豆批发利润 > 广告获客成本 时，模型成立
```

## 十一、落地路径

### 第一阶段：最小可用（MVP）

**目标：跑通"注册 → 领券 → 到店核销 → 补偿豆"闭环**

- 开发小程序基础版：注册、任务墙（签到 + 分享 + 邀请）、体验券、可用店铺列表
- 开发核销网页：商家扫码核销
- admin-dashboard 新增：商家管理（店铺信息、豆账户）、体验券管理
- 选择 3-5 家合作商家试点
- 小范围广告投放验证获客成本

### 第二阶段：完善运营

**目标：扩大规模，优化转化**

- 完善任务体系（看游戏介绍、完善资料等）
- 上线商家后台（店铺信息自助管理）
- 增加裂变功能（邀请海报、分享有礼）
- 扩大广告投放，优化 ROI
- 接入更多商家

### 第三阶段：生态化

**目标：小程序成为 VR 行业流量入口**

- VR 游戏库内容运营（游戏评测、推荐）
- LBS 店铺地图（参与商家多了再做）
- 店铺付费排名/广告位
- 数据看板（商家经营分析、平台营销效果）
- 跨城市扩张

## 十二、风险与应对

| 风险 | 应对 |
|---|---|
| 玩家领券后不到店 | 体验券设有效期，过期自动作废；广告投放精准定向 |
| 商家不愿意扫码核销 | 强调零成本 + 免费豆补偿；只在参与商家中投放广告 |
| 玩家刷积分 | 每人同时限 1 张体验券；邀请奖励在好友注册后发放；异常行为风控 |
| 广告获客成本过高 | 先小范围测试，找到成本最低的渠道后放量 |
| 商家自建小程序竞争 | 平台优势是跨店通用 + 广告投放能力，单店做不了 |
| 体验券玩家占用高峰时段 | 设置工作日券/闲时券，积分兑换价格不同 |

---

## 十三、总结

核心思路：**平台用广告获客，用体验券驱动到店，用虚拟豆补偿商家，用裂变降低获客成本，最终靠豆批发利润覆盖成本。**

平台与商家之间只有两笔交易：
1. 买机器（一次性）
2. 买游戏豆（持续采购）

营销方案不改变这两笔交易的结构，而是通过引流让第二笔交易量变大。

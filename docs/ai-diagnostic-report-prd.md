# AI 诊断报告 PRD

版本：v2.0  
日期：2026-09-14  
本期范围：总运营后台、商户后台报告查看与诊断发起

## 1. 产品目标

系统按已完成的数据周期，为各店铺生成 AI 经营诊断报告。运营人员可检索、查看和下载完整报告，并维护模板、生成规则和诊断资料。

本期采用“前端轻、后端重”的模式：

- 前端：报告检索、HTML 报告展示、配置与操作入口。
- 后端：数据快照、AI 生成、模板包校验、文件产物、权限同步、版本审计和调度任务。

## 2. 本期信息架构

运营后台「数据中心」下：

- AI 诊断报告
  - 报告记录
  - AI 诊断报告配置

报告同步至商户后台的规则由运营后台配置；商户仅能查看已同步至本商户的报告。

## 3. 角色权限

| 角色 | 权限 |
|---|---|
| 平台超管 / 运营管理员 | 查看全部报告；维护模板、规则、资料；生成新版本；同步历史报告；下载 |
| 商户管理员 / 店长 | 查看已同步报告；提交经营背景补充；下载报告 |

## 4. 报告记录

### 4.1 页面目标

集中查看不同商家、店铺、月份的已生成报告，进入完整 HTML 报告详情，并按需下载或同步历史报告。

### 4.2 筛选项

- 报告名称关键词
- 商家
- 店铺
- 报告月份
- 报告状态

筛选条件支持叠加。

### 4.3 列表字段

| 字段 | 说明 |
|---|---|
| 报告名称 | 店铺名称、报告月份和报告名称 |
| 店铺 / 商家 | 报告归属 |
| 报告月份 | 报告覆盖的数据周期 |
| 健康分 | 经营健康总分 |
| 状态 | 已生成 / 生成中 / 生成失败 |
| 商户可见 | 已同步 / 未同步 |
| 生成时间 | 报告生成完成时间 |
| 操作 | 查看、下载 |

生成失败的记录须展示失败状态和失败原因，并仅提供“重试生成”操作。

### 4.4 列表操作

- 查看：进入独立的完整 HTML 报告详情页。
- 下载：点击后选择 PDF 或 ZIP。
  - PDF 用于直接阅读或发送。
  - ZIP 包含 HTML 报告及相关资源产物。

操作区保持单行展示，只显示“查看”“下载”。

## 5. HTML 报告详情

报告详情为独立页面，不使用摘要弹窗。服务端保存 HTML 产物，前端负责安全渲染及基础操作。

### 5.1 内容结构

1. 报告封面：店铺、商家、报告周期、生成时间、模板版本、报告版本、数据快照时间。
2. 经营健康度：总分、健康等级及六维评分。
3. 核心经营指标：不超过六项，每项有趋势或环比。
4. 一页结论：整体状态、增长来源或拖累、下周期方向。
5. 问题、机会与建议：主要问题、增长机会、优先动作。
6. 下期行动计划：优先级、行动建议、负责人、验证指标。
7. 审计信息：数据快照版本、模板版本、资料库版本、生成时间和报告版本。

报告详情还须展示：

- 数据依据：营收与订单、会员、设备、内容等来源的快照时间和覆盖内容。
- 报告版本历史：版本号、生成时间、中性更新类型、可选更新说明和当前版本状态；不展示平台技术问题。

六维评分包括：营收增长力、客流活跃度、会员质量、设备效率、内容吸引力、运营执行力。

### 5.2 详情操作

- 生成新版本：基于当前选定数据快照和该周期已保存的店长补充创建新版本，不覆盖历史版本。
- 更新说明：运营后台可选填写，选择“其他”更新类型时必填；商户侧不展示。
- 同步至商户：仅对未同步的历史报告开放；新增商户查看权限，不重新生成内容。
- 下载：选择 PDF 或 ZIP。

## 6. 商户同步

### 6.1 同步方式

生成规则可选择：

| 方式 | 行为 |
|---|---|
| 生成成功后自动同步商户后台 | 本次保存配置后新生成成功的报告自动可见 |
| 仅运营后台可见 | 新生成报告仅平台可见 |

选项下必须展示动态备注：

- 自动同步：仅影响本次保存后新生成成功的报告，历史报告不会自动同步。
- 仅运营后台可见：需要同步的历史报告在报告记录中逐份处理。

### 6.2 历史报告

- 修改同步方式不影响历史报告。
- 历史报告同步不需要重新生成。
- 同步后保留原报告内容、数据快照和生成版本。
- 报告记录通过“商户可见”展示同步状态。

## 7. 商户后台：AI 店铺经营诊断

### 7.1 页面目标

店长按门店和月份查看已同步的完整诊断报告；当某月份无报告时，可发起 AI 诊断，并可补充系统无法获取的真实经营背景。

### 7.2 页面形态

- 报告中心：按当前门店展示报告卡片列表，卡片包含报告月份、健康等级、健康分、生成时间。
- 报告详情：点击“查看报告”进入完整报告阅读页；详情页提供返回报告中心入口。
- 每张报告卡片均提供“补充经营背景”，补充内容与该报告周期独立关联。
- 无报告：展示空状态和“补充本月经营背景”入口。
- 报告内容：健康度、指标快照、一页结论、店长补充、问题、机会、行动计划。
- 下载：商户可下载 PDF、ZIP。

### 7.3 店长经营背景补充

报告由系统按月自动生成，店长不能手动发起诊断或生成报告。

1. 店长选择需要补充的报告月份。
2. 系统展示 3 个可选问题：活动或营业调整、设备/人员/外部客流影响、优先改善问题。
3. 店长填写补充或直接跳过。
4. 系统保存补充内容，供该月份下一次自动生成的报告引用。
5. 调度任务按平台生成规则锁定数据快照，并结合补充生成报告。

店长补充只进入本期报告上下文，不修改订单、会员、设备等真实业务数据，也不会立即生成或改写历史报告。运营后台后续生成同一周期的新版本时，可引用当时已保存的店长补充；每个报告版本须固化其实际引用的补充内容。

## 8. AI 诊断报告配置

配置页为一个连续页面，包含报告模板、生成规则、诊断资料三个区块，不使用标签页拆分。

### 7.1 报告模板设置

页面主区只展示当前启用模板名称和状态。

点击“选择模板”打开弹窗：

- 展示模板名称、版本、资源包信息。
- 选择后确认设为当前启用模板。
- 当前启用模板不可删除；需先切换到其他模板。
- 非当前模板可删除。

上传新模板：

- 输入模板名称。
- 选择 ZIP 模板包。
- 模板包由 HTML 页面和 JSON 资源组成。
- 前端校验 ZIP 格式。
- 服务端校验包内必须存在 index.html、manifest.json、合法 JSON Schema、完整资源引用及安全内容。
- 校验通过后才可设为启用。

### 7.2 生成规则

生成规则全部使用标准组件，不使用自由文本。

| 配置项 | 组件 | 说明 |
|---|---|---|
| 数据范围 | 下拉选择 | 按月 / 按周 / 按季度 |
| 生成日期 | 联动下拉 | 随数据范围变化 |
| 生成时间 | 时间选择器 | 调度任务执行时间 |
| 同步方式 | 单选 | 自动同步 / 仅平台可见 |
| 失败重试次数 | 下拉选择 | 不重试或 1–3 次 |

数据范围与生成日期的联动：

- 按月：自动取上月完整数据，可选每月 1 / 2 / 3 日生成。
- 按周：自动取上周完整数据，可选每周一 / 二 / 三生成。
- 按季度：自动取上季度完整数据，可选每季首月 1 / 2 / 3 日生成。

### 7.3 诊断资料

诊断资料默认全平台生效，不设置适用范围。

| 字段 | 规则 |
|---|---|
| 资料名称 | 必填 |
| 资料类型 | 必填，下拉选择 |
| 资料内容 | 必填，多行文本，供 AI 引用 |
| 版本 | 系统维护 |
| 状态 | 已生效 |

列表展示资料名称、资料类型、内容摘要、版本、状态和编辑操作。

资料类型支持维护：

- 可新增自定义类型。
- 默认类型不可删除。
- 已被资料使用的类型不可删除。

## 9. 后端能力要求

### 8.1 报告生成链路

1. 根据数据范围锁定已完成周期。
2. 固化门店经营数据快照。
3. 读取当前启用模板和诊断资料版本。
4. 调用 AI 生成结构化报告数据。
5. 基于模板渲染 HTML。
6. 生成 PDF 和 ZIP 产物。
7. 写入报告、版本、快照、产物和审计记录。
8. 按同步方式设置商户查看权限。

### 8.2 核心实体

| 实体 | 核心字段 |
|---|---|
| Report | 店铺、商家、周期、状态、健康分、HTML 地址、商户可见状态 |
| ReportVersion | 报告版本、中性更新类型、可选更新说明、生成时间、店长补充快照、HTML/PDF/ZIP 产物 |
| DataSnapshot | 数据范围、快照时间、来源指标与版本 |
| TemplatePackage | 名称、版本、ZIP、校验状态、启用状态 |
| KnowledgeItem | 名称、类型、内容、版本、状态 |
| GenerationRule | 数据范围、生成日期、生成时间、同步方式、重试次数 |
| AuditLog | 操作人、时间、变更前后值、生成链路版本 |

具体的数据修正、任务失败、数据回补、模板校验等技术原因仅写入内部 AuditLog，不展示在报告本体、版本历史或商户侧。

## 10. 本期不包含

- 短信、邮件、企微等外部消息发送。
- 指标口径配置、模型提示词配置、生成任务日志页面。
- 平台普通手工批量生成；平台仅保留重新生成和失败重试能力。

## 11. 管理后台生成流程

本期流程仅覆盖管理后台能力，不进入商户后台交互。

1. 调度任务按生成规则锁定店铺已完成周期的数据快照。
2. 规则引擎计算指标、健康分、异常项和数据完整性。
3. 系统读取当前启用模板、诊断资料与规则配置，生成报告结构化内容。
4. 服务端渲染 HTML，并生成 PDF、ZIP 产物。
5. 系统归档报告、版本、数据快照、模板版本与资料库版本。
6. 系统按同步方式决定新报告是否自动对商户可见。
7. 运营人员在报告记录中处理失败原因、生成新版本、下载和历史报告同步。

店长补充由商户后台的经营背景补充入口采集；后端须记录补充内容、来源人、提交时间和对应报告版本。

## 12. 验收标准

- 可按商家、店铺、月份和状态筛选报告。
- 查看详情打开完整 HTML 报告，而非摘要弹窗。
- 报告包含健康度、指标、结论、问题/机会/建议、行动计划和审计信息。
- 下载提供 PDF、ZIP。
- 模板支持上传、校验、选择、启用和非当前模板删除。
- 生成规则使用下拉、单选、时间选择等标准组件。
- 数据范围联动生成日期，且自动取已完成周期数据。
- 自动同步仅影响配置保存后新生成报告；历史报告可逐份同步且不重新生成。
- 诊断资料必须有可编辑文本内容；默认类型和已使用类型不可删除。
- 商户仅可查看已同步至本商户的报告，并可按门店、月份查看当前报告。
- 商户可补充或跳过经营背景；补充内容仅影响对应月份后续自动生成的报告上下文。

# 头号空间 - 商家门店测试执行手册

> **适用版本**：v2.20 | **更新日期**：2026年7月28日
> **目标读者**：测试人员、产品验收人员、门店联调人员
> **覆盖系统**：商家后台（admin-dashboard Shop）+ PC 收银系统（cashier-ui）
> **文档目标**：测试人员按本文顺序执行，可完成门店侧核心功能验收

---

## 1. 使用说明

本文不是培训材料，而是测试执行手册。

执行原则：
- 按章节顺序测试，不建议跳测
- 每个用例都要记录实际结果、截图和异常描述
- 如前置条件不成立，先回到上游章节补齐，不直接判功能失败
- 以当前仓库 PRD `v2.20` 为唯一业务口径

通过标准：
- 核心主链路全部通过
- 关键异常分支至少各验证 1 次
- 菜单、入口、提示文案与当前版本一致

---

## 2. 测试范围

本手册覆盖以下门店核心链路：

1. 商家后台登录与菜单可见性校验
2. 设备列表与绑定关系校验
3. 收银终端 Token 创建、绑定、禁用校验
4. 点播系统密码设置校验
5. 商品、充值套餐、优惠券配置校验
6. 新会员仅手机号建档校验
7. 散客收银校验
8. 会员收银校验
9. 充值、订单、营收、交班校验
10. 异常订单闭环校验

不在本手册范围：
- IC 卡管理
- 员工卡设置
- 套票能力
- 第三方外围设备管理

以上能力当前版本均不作为门店必测项。

## 3. 测试前准备

执行前需确认以下条件已满足：

| 检查项 | 要求 |
|------|------|
| 商家账号 | 已创建，状态正常，可登录商家后台 |
| 店铺 | 已创建，至少 1 家门店可用 |
| 主机 | 至少 1 台主机已分配到门店 |
| 头显 | 至少 1 台头显已分配到同门店 |
| 内容 | 至少 1 个游戏已完成分发 |
| 收银终端 | 商家后台可新建收银终端并复制 Token |
| 测试账号 | 至少准备 1 个店长账号、1 个收银员账号 |
| 测试会员数据 | 准备 1 个本店已关联会员、1 个全局已存在但未关联会员、1 个全新手机号 |

推荐测试手机号：

| 场景 | 手机号 | 预期 |
|------|------|------|
| 已是本店会员 | `17600110765` | 不允许重复添加 |
| 全局已存在未关联本店 | `15812345678` | 自动关联到本店 |
| 全新会员 | 自备未使用手机号 | 创建最小档案 |

## 4. 菜单与入口基线

### 4.1 商家后台必看入口

测试人员登录商家后台后，至少应能看到以下模块：

| 模块 | 关键页面 |
|------|------|
| 商品管理 | 单次消费项目、实物商品 |

| 订单管理 | 收银订单、点播系统订单、异常订单 |

### 4.2 当前版本不应出现的入口

以下入口若被展示，应记录为版本不一致：

| 入口 | 预期 |
|------|------|
| IC 卡管理 | 不展示 |
| 员工卡设置 | 不展示 |
| 套票 | 不展示 |
| 第三方外围设备 | 不展示 |
| 商家后台支付设置 / 系统参数 | 不作为当前门店测试入口 |

## 5. 核心测试用例

## 5.1 用例 M01：商家后台登录成功

**目标**：确认门店账号可正常进入后台，首页和菜单加载正确。

**操作步骤**
1. 打开商家后台登录页。
2. 输入店长或管理员账号密码。
3. 点击登录。

**预期结果**
- 登录成功，进入“今日概况”
- 页面无空白、无报错
- 左侧菜单与本手册 4.1 一致

**失败判定**
- 无法登录
- 登录后跳错角色页面
- 菜单缺失或出现当前版本不应开放的入口

---

## 5.2 用例 M02：设备列表与绑定关系正确

**目标**：确认门店可看到官方已分配的主机和头显，且归属关系正确。

**操作路径**：系统设置 → 设备列表

**操作步骤**
1. 进入“主机设备”页签。
2. 核对主机编号、主机名称、MAC 地址、所属门店、在线状态。
3. 查看主机的绑定头显数量。
4. 切换到“头显设备”页签。
5. 核对头显名称、SN 码、型号、所属门店、绑定主机。

**预期结果**
- 主机和头显都可见
- 主机与头显所属门店一致
- 绑定关系与现场预期一致
- 头显详情页可查看电量、IPD、绑定主机等信息

**异常分支**
- 若头显属于其他门店，应无法绑定到当前主机
- 若当前店铺无主机，绑定主机弹窗应给出明确提示

---

## 5.3 用例 M03：门店补绑头显成功

**目标**：确认商家可在同店铺范围内补做设备绑定。

**操作路径**：系统设置 → 设备列表

**操作步骤**
1. 在“主机设备”中找到目标主机。
2. 点击“绑定头显”。
3. 输入同门店头显 SN 码。
4. 确认绑定。

**预期结果**
- 绑定成功
- 主机绑定头显数增加
- 头显详情中的绑定主机更新为目标主机

**异常分支**
- 输入不存在的 SN：提示未找到设备
- 输入异店头显 SN：提示不同门店，禁止绑定

---

## 5.4 用例 M04：设置点播系统密码成功

**目标**：确认门店可为主机设置点播系统管理密码。

**操作路径**：系统设置 → 设备列表 → 主机设备 → 修改点播系统密码

**操作步骤**
1. 选择一台主机。
2. 点击“修改点播系统密码”。
3. 输入新密码并确认。
4. 保存。

**预期结果**
- 保存成功
- 页面给出成功提示
- 后续点播系统进入管理模式时应要求输入该密码

**异常分支**
- 两次密码不一致：不允许保存
- 留空保存：如产品允许，则记录为“清空密码”；如不允许，则应拦截

---

## 5.5 用例 M05：新建收银终端并复制 Token

**目标**：确认商家后台可以为收银机生成 Token。

**操作路径**：系统设置 → 收银终端

**操作步骤**
1. 进入“收银终端”页面。
2. 点击“新建收银设备”。
3. 选择店铺，填写终端名称。
4. 记录系统自动生成的 Token。
5. 点击创建并复制 Token。

**预期结果**
- 新设备创建成功
- 列表出现新终端
- 初始状态为“未使用”
- Token 可复制

**异常分支**
- 终端名称为空：不允许创建
- 重复 Token：系统应阻止或自动重新生成

---

## 5.6 用例 M06：收银系统绑定本机成功

**目标**：确认 PC 收银系统必须先绑定 Token，才能登录。

**操作路径**：PC 收银系统登录页 → 更多菜单 → 基础配置

**操作步骤**
1. 打开收银系统登录页。
2. 不绑定 Token，直接尝试登录。
3. 进入“基础配置”。
4. 粘贴从商家后台复制的 Token。
5. 点击“绑定本机”。
6. 绑定成功后再次登录。

**预期结果**
- 未绑定时，登录被拦截
- 绑定成功后，显示设备名称、门店、脱敏 Token
- 再次登录可成功进入销售页

**异常分支**
- 输入无效 Token：提示 Token 无效
- 输入已被其他设备绑定的 Token：提示已被其他设备使用
- 输入已禁用 Token：提示该收银设备已被禁用

---

## 5.7 用例 M07：收银终端禁用后无法登录

**目标**：确认商家禁用终端后，该收银机不能继续登录。

**操作步骤**
1. 在商家后台“收银终端”找到已绑定设备。
2. 编辑该设备，将启用状态改为关闭。
3. 回到收银系统，刷新或重新进入业务页。

**预期结果**
- 收银端会话失效或无法再次登录
- 提示设备已被禁用

**备注**
- 当前原型重点验证“禁用后不可用”
- 关于同 Token 在线互踢，本版本以当前实现口径验证，不作为门店主通过标准

---

## 5.8 用例 M08：配置单次消费项目成功

**目标**：确认门店可配置可售卖项目。

**操作路径**：商品管理 → 单次消费项目

**操作步骤**
1. 新增或编辑单次消费项目。
2. 填写项目名称、时长、价格。
3. 保存后返回列表。

**预期结果**
- 项目保存成功
- 列表可见新项目
- 收银端可选到该项目

---

## 5.9 用例 M09：配置充值套餐与优惠券成功

**目标**：确认门店可配置会员运营规则。

**操作路径**
- 充值套餐：运营管理 → 充值套餐
- 优惠券：运营管理 → 优惠券

**操作步骤**
1. 新建一个充值套餐。
2. 设置充值金额、赠送金额。
3. 新建一张优惠券，设置有效期和门槛。

**预期结果**
- 两类配置均保存成功
- 收银端相关页面可看到对应活动或优惠能力

---

## 5.10 用例 M10：新增会员仅允许手机号建档

**目标**：确认 v2.20 的会员建档规则已经生效。

**操作路径**：收银系统 → 销售 → 新增会员

**操作步骤**
1. 输入“已是本店会员”的手机号。
2. 输入“全局已存在但未关联本店”的手机号。
3. 输入“全新手机号”。

**预期结果**
- 本店已存在：提示“该手机号已是本店会员”，不可重复添加
- 全局已存在未关联：提示“系统将自动关联到本店”，提交后成功关联
- 全新手机号：提示“系统将自动添加为本店会员”，提交后成功创建
- 整个流程中不要求填写姓名、性别、生日、备注

**失败判定**
- 仍要求输入完整会员资料
- 门店侧可覆盖全局档案字段
- 已有关联的手机号可重复创建

---

## 5.11 用例 M11：散客收银成功

**目标**：确认无会员场景可完成收银闭环。

**操作步骤**
1. 在销售页添加商品或体验项目。
2. 不选择会员。
3. 选择现金或扫码支付。
4. 完成结算。

**预期结果**
- 订单创建成功
- 成功页显示支付完成
- 订单列表可查询到该笔订单

---

## 5.12 用例 M12：会员收银成功

**目标**：确认会员识别、优惠和资产抵扣链路正常。

**操作步骤**
1. 在收银端搜索或选择会员。
2. 添加商品。
3. 进入结算。
4. 观察优惠和抵扣结果。
5. 完成支付。

**预期结果**
- 会员身份识别成功
- 系统按当前规则自动处理优惠和资产抵扣
- 资产足够时无需外部补差
- 资产不足时正确给出补差金额
- 支付成功后订单生成

---

## 5.13 用例 M13：会员充值成功

**目标**：确认充值套餐可正常使用。

**操作步骤**
1. 进入会员页并选中目标会员。
2. 选择充值。
3. 选择已配置的充值套餐。
4. 完成支付。

**预期结果**
- 充值订单创建成功
- 会员预存款余额增加
- 如配置赠送，赠送部分同步到账

---

## 5.14 用例 M14：订单与营收数据可查

**目标**：确认交易结果可回溯。

**操作路径**
- 收银系统：订单、营收、交班对账
- 商家后台：收银订单、历史营收统计、交接班记录

**操作步骤**
1. 完成至少 1 笔散客单、1 笔会员单、1 笔充值单。
2. 到订单页查询。
3. 到营收页查看汇总。
4. 执行一次交班。

**预期结果**
- 三类订单均可查到
- 营收统计有数据变化
- 交班记录生成成功

---

## 5.15 用例 M15：异常订单标记与处理闭环

**目标**：确认商家侧异常订单流程可用。

**操作路径**：商家后台 → 异常订单

**操作步骤**
1. 找到可测试订单，执行“标记异常”。
2. 确认订单进入异常列表。
3. 取消标记，确认可移出异常列表。
4. 对一笔已驳回异常单，查看驳回原因。
5. 执行“重新提交”或“自行解决”。

**预期结果**
- 可标记异常
- 可取消标记
- 已驳回状态可见驳回原因
- 可重新提交平台或自行解决

## 6. 测试完成标准

门店侧验收完成需同时满足：

1. 商家后台登录、设备查看、收银终端、商品、会员、订单、营收、交班均通过。
2. 收银系统完成 Token 绑定、会员建档、散客收银、会员收银、充值测试。
3. 当前版本暂隐能力未误开放。
4. 异常订单链路至少验证 1 次。

## 7. 常见判错点

以下情况不要直接记为“功能坏了”：

| 现象 | 先检查什么 |
|------|------|
| 收银无法登录 | 是否已先绑定 Token |
| 看不到头显或主机 | 是否由平台侧完成分配 |
| 绑定头显失败 | 是否为同一店铺 |
| 新会员不能输入姓名生日 | 这是当前版本正确行为 |
| 找不到 IC 卡或员工卡入口 | 这是当前版本正确行为 |
| 找不到套票入口 | 这是当前版本正确行为 |

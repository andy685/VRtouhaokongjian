# 头号空间 - 官方运营测试执行手册

> **适用版本**：v2.20 | **更新日期**：2026年7月28日
> **目标读者**：测试人员、运营验收人员、实施交付人员
> **覆盖系统**：总运营后台（admin-dashboard Platform）
> **文档目标**：测试人员按本文顺序执行，可完成官方交付链路核心验收

---

## 1. 使用说明

本文用于测试执行，不用于角色培训。

执行要求：
- 按“商家开通线 → 设备交付线 → 内容分发线 → 支付配置线 → 下游联动验证”顺序执行
- 每个用例都要记录实际结果和截图
- 只有当下游结果可见，才算上游功能真正通过

通过标准：
- 商家、店铺、主机、头显、内容分发、支付配置全部走通
- 门店侧能基于官方交付结果完成登录、绑定、下载和首单测试

---

## 2. 测试范围

本手册覆盖以下官方核心能力：

1. 平台后台登录与菜单校验
2. 新建商家
3. 新建店铺
4. 录入主机并分配门店
5. 生成或管理点播系统 Token
6. 录入头显并绑定主机
7. 内容分发
8. 拉卡拉配置
9. 交付结果校验
10. 对下游异常的定位确认

---

## 3. 测试前准备

| 检查项 | 要求 |
|------|------|
| 平台账号 | 可登录 Platform 角色 |
| 商家样例数据 | 可新建 1 个全新商家 |
| 店铺样例数据 | 可在新商家下创建至少 1 家店铺 |
| 设备资料 | 至少准备 1 台主机、1 台头显的编号或 SN 信息 |
| 游戏内容 | 至少准备 1 个可上线或可分发游戏 |
| 支付资料 | 至少准备 1 组可测试的支付配置示例 |

建议新建一套完整的测试商家，避免污染旧演示数据。

---

## 4. 平台菜单基线

登录平台后台后，至少应能看到以下模块：

| 模块 | 关键页面 |
|------|------|
| 店铺管理 | 商家管理、店铺列表、代理商 |
| 内容中心 | 游戏库、内容分发、游戏审核 |
| 数据中心 | 设备配置管理、设备运行总览 |
| 平台财务 | 营收总览、异常订单、拉卡拉配置、结算管理 |
| 平台通知 | 公告管理、消息推送、系统通知 |
| 帮助与运维 | 帮助文档、FAQ、版本发布、操作日志 |

如菜单缺失、跳转错误或显示了与当前角色不匹配的内容，应记录为问题。

## 5. 核心测试用例

## 5.1 用例 O01：平台后台登录成功

**目标**：确认平台超管可正常进入总运营后台。

**操作步骤**
1. 打开平台登录页。
2. 输入平台账号密码。
3. 点击登录。

**预期结果**
- 成功进入“大屏看板”
- 左侧菜单正常展示
- 页面无报错、无空白

---

## 5.2 用例 O02：新建商家成功

**目标**：确认平台可创建新的商家主体，并为商家生成后台账号。

**操作路径**：店铺管理 → 商家管理

**操作步骤**
1. 点击“新增商家”。
2. 填写商家名称、联系人、联系电话、区域、代理归属、手续费率。
3. 填写商家管理员账号和密码。
4. 保存。

**预期结果**
- 商家创建成功
- 列表可看到新商家
- 状态可设置为“正常”
- 商家拥有后台登录凭证

**失败判定**
- 商家保存后列表不可见
- 状态异常导致后续无法使用
- 管理员账号未生成或无法使用

---

## 5.3 用例 O03：新建店铺成功

**目标**：确认平台可在商家下创建门店，并生成注册码。

**操作路径**：店铺管理 → 店铺列表

**操作步骤**
1. 点击“新增店铺”。
2. 选择所属商家。
3. 填写店铺名称、所属区域、详细地址、联系电话、状态。
4. 保存。

**预期结果**
- 店铺创建成功
- 店铺可挂到目标商家下
- 店铺列表中可见新门店
- 可生成或展示注册码

---

## 5.4 用例 O04：录入主机并分配到店铺

**目标**：确认平台可录入点播主机，并完成门店分配。

**操作路径**：数据中心 → 设备配置管理 → 主机管理

**操作步骤**
1. 点击“录入主机”。
2. 填写主机编号、主机名称、设备类型、配置、系统版本、MAC 地址。
3. 保存后，在列表中执行“分配”。
4. 选择商家和店铺并确认。

**预期结果**
- 主机录入成功
- 主机分配成功
- 分配后归属商家和店铺正确

**异常分支**
- MAC 地址为空：不应保存
- 未分配店铺时，下游门店不应可正常使用

---

## 5.5 用例 O05：生成 Token 并可交付下游

**目标**：确认平台侧主机 Token 可生成并用于门店点播系统配置。

**操作步骤**
1. 在已分配主机的行内点击“生成 Token”或相应操作。
2. 记录 Token。
3. 确认 Token 状态为可用。

**预期结果**
- Token 成功生成
- Token 可复制
- 该 Token 可交给门店在点播系统填写

**注意**
- 这里验证的是主机 / 点播系统 Token
- 与商家后台“收银终端”中的收银 Token 不是同一类能力

---

## 5.6 用例 O06：录入头显并绑定主机

**目标**：确认平台可录入头显，并绑定到同店铺主机。

**操作路径**：数据中心 → 设备配置管理 → 头显管理

**操作步骤**
1. 点击“录入头显”。
2. 填写头显名称、型号、SN、固件版本。
3. 保存。
4. 为头显执行“分配”，选择目标商家和店铺。
5. 执行“绑定到主机”，选择同店铺主机。

**预期结果**
- 头显录入成功
- 头显分配成功
- 绑定成功后，主机与头显建立关系

**异常分支**
- 异店主机不应出现在可绑定范围内
- SN 重复应被拦截或提示异常

---

## 5.7 用例 O07：内容分发成功

**目标**：确认平台可将游戏分发到指定门店，门店后续可拉取内容。

**操作路径**：内容中心 → 内容分发

**操作步骤**
1. 找到目标游戏。
2. 点击“分发”。
3. 选择目标店铺。
4. 选择分发方式，优先测试“智能分发”。
5. 提交任务。
6. 查看分发详情。

**预期结果**
- 分发任务创建成功
- 状态能从未分发进入分发中，再进入已分发
- 门店后续应能看到对应内容

**异常分支**
- 任务失败时应可重试
- 单店铺分发状态应可单独查看

---

## 5.8 用例 O08：拉卡拉配置保存成功

**目标**：确认平台可维护支付配置，为门店支付测试提供前提。

**操作路径**：平台财务 → 拉卡拉配置

**操作步骤**
1. 进入拉卡拉配置页。
2. 录入商户号、终端号、机构号等信息。
3. 上传证书或补充必要字段。
4. 保存。

**预期结果**
- 配置保存成功
- 页面无校验异常
- 可作为门店微信 / 支付宝测试前置条件

---

## 5.9 用例 O09：平台交付结果可被门店消费

**目标**：确认平台交付结果不只是“保存成功”，而是真的能驱动下游使用。

**联动检查项**

| 交付项 | 下游验证方式 |
|------|------|
| 商家账号 | 商家后台可登录 |
| 店铺 | 商家后台可看到店铺 |
| 主机 | 商家后台设备列表可看到主机 |
| 头显 | 商家后台设备列表可看到头显 |
| 主机 Token | 门店点播系统可填写并识别 |
| 内容分发 | 门店终端可看到目标内容 |
| 支付配置 | 门店可执行首单支付测试 |

**通过标准**
- 上表至少逐项验证通过后，才算本轮官方交付链路通过

---

## 5.10 用例 O10：异常定位能力可支持下游排查

**目标**：确认当门店反馈问题时，平台测试人员知道先查哪里。

建议至少演练以下 4 类问题：

| 门店现象 | 平台先查哪里 | 预期判断 |
|------|------|------|
| 门店看不到游戏 | 内容分发 | 是否分发成功 |
| 头显无法绑定主机 | 设备配置管理 | 是否同店铺、是否已分配 |
| 点播系统无法识别 Token | 主机管理 | Token 是否生成、是否已吊销 |
| 门店不能支付 | 拉卡拉配置 | 支付配置是否齐全 |

---

## 6. 完成标准

官方侧测试通过需同时满足：

1. 商家和店铺可成功创建。
2. 主机和头显可成功录入、分配、绑定。
3. Token 可成功生成并交付。
4. 内容可成功分发到门店。
5. 支付配置可成功保存。
6. 下游门店可基于上述结果完成基础使用验证。

---

## 7. 常见判错点

| 现象 | 不要直接下结论，先确认 |
|------|------|
| 门店看不到内容 | 先看内容是否已分发，而不是先怀疑门店不会操作 |
| 门店无法绑定头显 | 先看设备是否同店铺归属 |
| 商家登录不了收银 | 先区分是商家后台账号问题，还是收银 Token 未绑定 |
| 门店收款失败 | 先确认平台支付配置是否完成 |
